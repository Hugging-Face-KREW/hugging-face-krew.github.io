# LFM2.5-24B-A2B로 디바이스에서 빠르고 프라이빗한 에이전트 실행하기

[LFM2.5-24B-A2B](https://huggingface.co/LiquidAI/LFM2.5-24B-A2B)는 2B개의 활성 파라미터만 사용하는 24B 파라미터 추론 모델로, 디바이스에서 빠르고 프라이빗한 에이전트를 실행하도록 설계되었습니다. 답변하기 전에 사고하고, 도구를 호출하며, 널리 사용되는 에이전트 하니스 내부에서 여러 단계의 작업을 수행합니다. 토큰당 2B개의 파라미터만 활성화되므로 각 추론 토큰의 비용이 낮아, 자체 하드웨어에서 에이전트를 지속적으로 실행할 수 있습니다.

- 동급 최고 수준의 에이전트: 에이전트 및 도구 사용 작업에서 전체 및 활성 파라미터가 약 50% 더 많은 모델인 Qwen3.6-35B-A3B와 경쟁하며, LiveClaw에서 38.19 대비 48.09를 기록했습니다.

- MoE 속도의 추론: 답변하기 전에 항상 사고합니다. 토큰당 2B개의 활성 파라미터만 사용하므로 각 추론 토큰의 비용이 낮습니다.

- 효율적인 추론: Apple M5 Max에서 184 tok/s, 단일 NVIDIA B300 GPU에서 최대 21K output tok/s를 제공합니다.

[![LFM2.5-24B-A2B-benchmark](https://huggingface.co/LiquidAI/LFM2.5-24B-A2B/resolve/main/figures/LFM2.5-24B-A2B-benchmark.png)](https://huggingface.co/LiquidAI/LFM2.5-24B-A2B/resolve/main/figures/LFM2.5-24B-A2B-benchmark.png)

## 2B개의 활성 파라미터를 사용하는 추론 에이전트를 구축한 방법 {#section-1}

LFM2.5-24B-A2B는 [LFM2-24B-A2B](https://huggingface.co/LiquidAI/LFM2-24B-A2B)를 기반으로 하며 아키텍처를 그대로 유지합니다. 즉, 40개 레이어, 각 MoE 블록의 64개 전문가와 top-4 라우팅, 그리고 gated short convolution과 GQA를 결합한 동일한 구조를 사용합니다. 컨텍스트 윈도우는 32K 토큰에서 131K 토큰으로 확장되었으며, [in-place tokenizer expansion](https://www.liquid.ai/blog/tokenizer-expansion)가 어휘를 65K 토큰에서 128K 토큰으로 두 배 늘려 비라틴어 토큰화를 개선합니다. 이전 모델과 달리, 이 모델은 최종 답변 전에 명시적인 사고 사슬을 생성하는 추론 전용 모델입니다.

사전 학습 규모는 약 17T 토큰에서 약 33T 토큰으로 확대되었습니다. 이후 중간 학습에서는 32K 컨텍스트에서 추론, 수학, 코드, 지시 따르기, 다국어 텍스트에 가중치를 둔 2T 토큰을 추가하고, 131K 컨텍스트에서 긴 컨텍스트 데이터에 가중치를 둔 300B 토큰을 추가합니다. 도구 호출과 멀티턴 궤적은 두 단계 전반에 걸쳐 포함됩니다. 사후 학습에서는 다음 다섯 단계로 기본 모델을 에이전트로 전환합니다.

- 지도 미세 조정(SFT)

- 교사 전문화

- 다중 도메인 온폴리시 증류(MOPD), 비에이전트 방식: 비에이전트 작업에서 전문 교사 모델을 증류합니다.

- MOPD, 에이전트 방식: 에이전트 작업에 집중하는 두 번째 증류 단계입니다.

- 에이전트 강화 학습(Agentic RL): [OpenClaw](https://openclaw.ai), [Hermes Agent](https://hermes-agent.nousresearch.com), [Pi](https://pi.dev), [OpenCode](https://opencode.ai)와 같은 에이전트 하니스 내부에서 모델을 학습합니다.

## 벤치마크 결과 {#section-2}

도구 사용 및 에이전트 워크플로, 지식, 지시 따르기, 수학, 코딩을 다루는 16개 벤치마크에서 LFM2.5-24B-A2B를 Qwen3.6-35B-A3B, Gemma-4-26B-A4B-it, Nemotron-3.5-Lightning과 비교 평가했습니다. 이 그룹에서 가장 작은 모델임에도 전체 및 활성 파라미터가 약 50% 더 많은 MoE 모델들과 경쟁력 있는 성능을 보였습니다.

애플리케이션에서 특히 강점을 보이는 영역은 도구 사용과 지시 따르기입니다. LFM2.5-24B-A2B는 8개의 도구 사용 및 에이전트 벤치마크 중 5개(AutomationBench, BFCLv4, ToolSandbox, LiveClaw, τ³-Bench Banking)에서 경쟁 모델을 앞서거나 동률을 기록했으며, AutomationBench에서는 차상위 모델보다 3배 이상 높은 점수를 기록했습니다. 또한 3개의 지시 따르기 벤치마크 모두에서 선두를 차지했습니다. GPQA Diamond, HLE, AA-Omniscience와 같은 지식 중심 벤치마크 및 SWE-Bench Verified (OpenCode), SciCode와 같은 코딩 벤치마크에서는 더 큰 모델이 여전히 우위를 보이므로, 지식 중심 워크로드에는 LFM2.5-24B-A2B를 검색 또는 웹 검색과 함께 사용하는 것이 좋습니다.

이러한 결과를 바탕으로 LFM2.5-24B-A2B는 추론하고, 도구를 호출하며, 사용자의 디바이스에서 안정적으로 실행되어야 하는 에이전트를 위한 강력한 기반이 됩니다.

## CPU 및 GPU에서의 추론 속도 {#section-3}

LFM2.5-24B-A2B는 llama.cpp, MLX, vLLM, SGLang, ONNX를 포함한 추론 생태계 전반에서 출시 첫날부터 지원됩니다.

엣지 추론. LFM2.5-24B-A2B는 비교한 MoE 모델 중 가장 빠르며, M5 Max에서 184 tokens/s, Ryzen AI Max+ 395에서 114 tokens/s로 디코딩합니다. 이는 메모리를 가장 적게 사용하면서도 차상위 모델보다 최대 1.7배 빠른 속도입니다.

[![LFM2.5-24B-A2B-edge-inference](https://huggingface.co/LiquidAI/LFM2.5-24B-A2B/resolve/main/figures/LFM2.5-24B-A2B-edge-inference.png)](https://huggingface.co/LiquidAI/LFM2.5-24B-A2B/resolve/main/figures/LFM2.5-24B-A2B-edge-inference.png)

GPU 추론. LFM2.5-24B-A2B는 동급 크기 모델 중 가장 빠르며, 단일 B300에서 높은 동시성으로 초당 21K output tokens를 넘는 처리량을 달성합니다.

[![LFM2.5-24B-A2B-gpu-inference](https://huggingface.co/LiquidAI/LFM2.5-24B-A2B/resolve/main/figures/LFM2.5-24B-A2B-gpu-inference.png)](https://huggingface.co/LiquidAI/LFM2.5-24B-A2B/resolve/main/figures/LFM2.5-24B-A2B-gpu-inference.png)

## LFM2.5-24B-A2B 사용 방법 {#section-4}

추론하고, 도구를 호출하며, 사용자의 디바이스에서 안정적으로 실행되는 에이전트가 필요할 때 LFM2.5-24B-A2B를 사용하세요.

`transformers`의 최신 버전을 설치하세요(`transformers>=5.0.0`와 호환됨).

```
pip install -U transformers
```


그런 다음 모델을 로드하고 실행합니다.

```
from transformers import AutoModelForCausalLM, AutoTokenizer, TextStreamer

model_id = "LiquidAI/LFM2.5-24B-A2B"
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    device_map="auto",
    dtype="bfloat16",
#   attn_implementation="flash_attention_2" <- uncomment on compatible GPU
)
tokenizer = AutoTokenizer.from_pretrained(model_id)
streamer = TextStreamer(tokenizer, skip_prompt=True, skip_special_tokens=True)

prompt = "What is C. elegans?"

input_ids = tokenizer.apply_chat_template(
    [{"role": "user", "content": prompt}],
    add_generation_prompt=True,
    return_tensors="pt",
    tokenize=True,
)["input_ids"].to(model.device)

output = model.generate(
    input_ids,
    do_sample=True,
    temperature=0.1,
    top_k=50,
    repetition_penalty=1.05,
    max_new_tokens=512,
    streamer=streamer,
)
```


### 에이전트 하니스에서 사용하기

OpenAI 호환 백엔드 뒤에서 LFM2.5-24B-A2B를 로컬로 서비스한 다음, 에이전트 하니스가 해당 엔드포인트를 가리키도록 설정하세요. 예를 들어 Hermes Agent를 사용하는 경우 다음과 같습니다.

```
hermes config set model.provider custom
hermes config set model.base_url http://localhost:8080/v1
hermes config set model.default LFM2.5-24B-A2B
hermes config set model.context_length 131072
hermes config set model.api_mode chat_completions
hermes config set agent.tool_use_enforcement true
```


포트는 사용하는 서비스 백엔드에 따라 다릅니다. llama.cpp와 MLX는 `8080`, vLLM은 `8000`, SGLang은 `30000`, LM Studio는 `1234`을 사용합니다. OpenClaw 및 Pi 설정은 [model card](https://huggingface.co/LiquidAI/LFM2.5-24B-A2B)을, 전체 설정 방법은 [our guide](https://docs.liquid.ai/examples/agent-harnesses)을 참조하세요. 동영상 예시는 [release blog](https://www.liquid.ai/blog/lfm2-5-24b-a2b)에서 확인할 수 있습니다.

## LFM2.5-24B-A2B 시작하기 {#section-5}

LFM2.5-24B-A2B와 LFM2.5-24B-A2B-Base는 모두 오픈 웨이트 모델이며 현재 Hugging Face에서 이용할 수 있습니다.

- 다운로드: Hugging Face에서 [LFM2.5-24B-A2B-Base](https://huggingface.co/LiquidAI/LFM2.5-24B-A2B-Base) 및 [LFM2.5-24B-A2B](https://huggingface.co/LiquidAI/LFM2.5-24B-A2B)을 다운로드하세요.

- 하니스에서 사용: OpenClaw, Hermes Agent, Pi와 같은 로컬 에이전트를 실행하는 방법은 [guide](https://docs.liquid.ai/examples/agent-harnesses)을 따르세요.

- 미세 조정: [fine-tuning tutorials](https://github.com/Liquid4All/cookbook/tree/main/finetuning/notebooks)을 사용해 LFM2.5-24B-A2B를 작업에 맞게 조정하세요.

여러분이 무엇을 만들어낼지 기대됩니다.
