Diffusers에서 FLUX.3 Image Klein을 만나보세요: Black Forest Labs의 최신 오픈 이미지 생성 모델

Black Forest Labs FLUX.3 Image Klein이 출시되었으며, 첫날부터 Diffusers에서 실행할 수 있습니다. 하나의 모델로 텍스트-이미지와 다중 참조 이미지-이미지를 모두 수행할 수 있고, 새로운 기능인 layout control도 추가되었습니다. 프롬프트에 bounding box를 작성해 이미지의 각 부분이 어디에 배치되어야 하는지, 또는 참조 이미지의 어느 부분을 이동할지 지정할 수 있습니다.

두 가지 오픈 체크포인트가 FLUX.3 Image Klein collection에 있습니다:

체크포인트 설명 기본값
black-forest-labs/flux-3-image-klein 타임스텝 증류 모델로, 빠른 추론에 적합 16 steps, no CFG
black-forest-labs/flux-3-image-klein-base 기본 모델 50 steps, CFG

지금 바로 Hugging Face space으로 이동해 이미지를 생성해 볼 수 있습니다!

한눈에 보기

  • 텍스트-이미지, 다중 참조 이미지-이미지, bounding-box layout control을 하나의 모델로 지원합니다.
  • 증류 체크포인트는 H100에서 약 2초 만에 1024 × 1024 이미지를 생성합니다.
  • NVFP4 및 FP8 가중치는 from_single_file으로 로드할 수 있어 소형 GPU에서도 사용할 수 있습니다.
  • 텍스트-이미지와 이미지 편집을 위한 LoRA 학습 스크립트를 제공합니다.
  • Modular Diffusers pipeline으로 제공되므로 블록을 분리하거나 직접 추가할 수 있습니다.

시작하기

최신 diffusers 및 transformers(Qwen3-VL 텍스트 인코더용)를 설치합니다:

pip install -U diffusers transformers

증류 체크포인트를 로드하고 이미지를 생성합니다:

import torch
from diffusers import ModularPipeline

pipe = ModularPipeline.from_pretrained("black-forest-labs/flux-3-image-klein")
pipe.load_components(dtype=torch.bfloat16)
pipe.to("cuda")

pipe(prompt="a red fox", output="images")[0].save("fox.png")

FLUX.3으로 할 수 있는 작업

텍스트-이미지

FLUX.3은 피사체, 배경, 조명, 구도, 스타일을 포함한 전체 장면 설명에 가장 잘 반응합니다. Black Forest Labs의 official prompting guide에 더 많은 팁이 있습니다. 증류 체크포인트는 기본적으로 16 steps에서 1024 × 1024 이미지를 생성합니다. height, width 또는 num_inference_steps를 전달해 값을 변경할 수 있습니다.

prompt = (
    "A wide-angle wildlife photograph of a red fox standing alert in a snow-covered forest clearing at golden hour. "
    "The fox is centered in the frame, its thick orange winter coat contrasting with the fresh white snow, breath "
    "visible in the cold air. Snow-laden pine trees fill the softly blurred background, and low warm sunlight rakes "
    "across the scene from the left, casting long blue shadows."
)

fox = pipe(
    prompt=prompt,
    generator=torch.Generator().manual_seed(0),
    output="images"
)[0]
fox.save("fox.png")
텍스트-이미지

이미지-이미지

image 인자로 참조 이미지(또는 여러 이미지)를 전달합니다. 변경 사항을 포함해 원하는 이미지의 캡션처럼 프롬프트를 작성합니다.

prompt = (
    "The same red fox in the same snow-covered forest clearing, now at night under a full moon: cool blue "
    "moonlight, deep shadows, stars visible through the pine branches, the fox's eyes catching the light."
)
night = pipe(
    prompt=prompt,
    image=fox, # from the previous text to image example
    generator=torch.Generator().manual_seed(0),
    output="images",
)[0]
night.save("night.png")
이미지-이미지

여러 참조 이미지를 사용하는 경우, image에 전달하는 순서에 따라 프롬프트에서 <ref_image_0>, <ref_image_1>, …로 참조합니다:

red_fox = pipe(prompt="a red fox", generator=torch.Generator().manual_seed(0), output="images")[0]
bench = pipe(prompt="a wooden bench", generator=torch.Generator().manual_seed(0), output="images")[0]

combined = pipe(
    prompt="The fox from <ref_image_0> sitting on the wooden bench from <ref_image_1> in a snowy setting.",
    image=[red_fox, bench],
    output="images",
)[0]

combined.save("combined.png")
<ref_image_0>: 빨간 여우 <ref_image_1>: 나무 벤치 벤치 위의 여우

Layout control

캡션 뒤에 영역 목록을 JSON 형식으로 추가합니다. 각 영역에는 id, bbox, desc가 있으며, 캡션에서는 <id>로 언급합니다.

[!NOTE] 상자는 0–1000 스케일에서 [y_min, x_min, y_max, x_max] 형식으로 작성하며, y가 먼저입니다. 스케일이 정규화되어 있으므로 동일한 상자를 어떤 이미지 크기에서도 사용할 수 있습니다.

새 이미지에 영역 배치하기

layout_prompt = (
    "Minimalist graphic illustration featuring a black silhouette of a person <silhouette_1> centered against a "
    "solid, vibrant chartreuse background <background_1>. The figure is captured in a dynamic, mid-stride running "
    "pose, facing toward the left side of the frame. "
    '[{"id": "background_1", "bbox": [0, 0, 1000, 1000], "desc": "A flat field of neon yellow-green with a subtle '
    'paper texture and fine, organic grain."}, {"id": "silhouette_1", "bbox": [150, 150, 850, 850], "desc": "A '
    "black silhouette of a person in motion, made of dense stippled ink. The leading edges are solid; the trailing "
    'arm and leg dissolve into coarse square pixels and scattered dots."}]'
)

runner = pipe(prompt=layout_prompt, generator=torch.Generator().manual_seed(0), output="images")[0]
각 영역의 desc이(가) 해당 bbox 내부에 그려집니다

참조 이미지 내에서 영역 이동하기

편집 시 각 영역은 콘텐츠가 어디에서 오는지(참조 이미지의 src_bbox)와 어디로 이동하는지(출력의 tgt_bbox)를 지정합니다. 두 상자가 동일한 영역은 원래 위치에 그대로 남습니다.

이 예제에서는 뜨개질한 기사를 왼쪽 위로 이동하고, 배경, 절벽, 바늘, 용, 불은 고정합니다:

from diffusers.utils import load_image

knight_image = load_image("knight_orig.png")
edit_prompt = (
    "In <ref_image_0>, move the miniature grey amigurumi knight figure <knight_1> upwards and to the left along the "
    "yarn cliff <cliff_1>. Keep the rest of the image completely unchanged, preserving the blurred yarn backdrop "
    "<backdrop_1>, the large knitted dragon <dragon_1>, and the fiery orange thread <fire_1>. "
    '[{"id": "knight_1", "from": "ref_image_0", "src_bbox": [500, 150, 850, 350], "tgt_bbox": [194, 55, 544, 255], '
    '"desc": "A miniature amigurumi knight crocheted from thick grey woolen yarn."}, '
    '{"id": "backdrop_1", "from": "ref_image_0", "src_bbox": [0, 0, 1000, 1000], "tgt_bbox": [0, 0, 1000, 1000], '
    '"desc": "A soft, out-of-focus backdrop of cream and indigo knitted yarn."}, '
    '{"id": "cliff_1", "from": "ref_image_0", "src_bbox": [300, 0, 1000, 450], "tgt_bbox": [300, 0, 1000, 450], '
    '"desc": "A steep cliff of stacked yarn skeins in mustard, terracotta, and indigo."}, '
    '{"id": "needle_1", "from": "ref_image_0", "src_bbox": [420, 250, 550, 450], "tgt_bbox": [420, 250, 550, 450], '
    '"desc": "An oversized polished steel tapestry needle."}, '
    '{"id": "dragon_1", "from": "ref_image_0", "src_bbox": [100, 600, 950, 1000], "tgt_bbox": [100, 600, 950, 1000], '
    '"desc": "A large, fluffy knitted dragon in terracotta and mustard yarn."}, '
    '{"id": "fire_1", "from": "ref_image_0", "src_bbox": [350, 400, 650, 650], "tgt_bbox": [350, 400, 650, 650], '
    '"desc": "Curled puffs of fiery orange angora thread suspended in mid-air."}]'
)

moved = pipe(prompt=edit_prompt, image=knight_image, generator=torch.Generator().manual_seed(0), output="images")[0]
기사는 src_bbox에서 tgt_bbox로 이동하고, 장면의 나머지 부분은 그대로 유지됩니다

기본 모델 및 양자화 변형

기본 모델

위의 모든 예제에서는 증류 체크포인트를 사용합니다. 기본 체크포인트는 classifier-free guidance를 사용해 50 steps로 실행되며, fine-tune에 사용할 체크포인트입니다(LoRA finetuning 참조).

pipe = ModularPipeline.from_pretrained("black-forest-labs/flux-3-image-klein-base")
pipe.load_components(dtype={"vae": torch.float32, "default": torch.bfloat16})
pipe.to("cuda")

pipe.guider = pipe.guider.new(guidance_scale=5.0)  # optional
image = pipe(prompt=prompt, output="images")[0]

단일 파일 형식 체크포인트

Black Forest Labs는 transformer를 bf16 단일 파일로도 제공하며, 두 가지 양자화 형식인 fp8r(rowwise FP8)과 nvfp4도 제공합니다. 이 중 어느 것이든 from_single_file으로 로드한 다음, 다른 구성 요소를 이름으로 로드하면 bf16 transformer가 다시 다운로드되지 않습니다.

from diffusers import BFLQuantizationConfig, Flux3Transformer2DModel, ModularPipeline

model_id = "black-forest-labs/flux-3-image-klein-base"
variant = "fp8r"  # or "nvfp4"

transformer = Flux3Transformer2DModel.from_single_file(
    f"https://huggingface.co/{model_id}/blob/main/variants/{variant}/model.safetensors",
    config=model_id,
    subfolder="transformer",
    quantization_config=BFLQuantizationConfig(compute_dtype=torch.bfloat16),
    dtype=torch.bfloat16,
)

pipe = ModularPipeline.from_pretrained(model_id)
pipe.load_components(dtype=torch.bfloat16)
pipe.update_components(transformer=transformer)
pipe.to("cuda")

양자화하지 않은 단일 파일에는 https://huggingface.co/{model_id}/blob/main/model.safetensors을 사용하고 quantization_config을 제거합니다.

변형 Fast kernels 사용 가능 환경 기타 GPU
fp8r Compute capability 8.9+ (Ada, Hopper, Blackwell) 매 step마다 가중치를 dequantize하므로 메모리는 줄지만 속도 향상은 없음
nvfp4 flashinfer-python 및 flashinfer-cubin이(가) 동일한 버전인 Blackwell 위와 동일

LoRA fine-tuning

FLUX.3은 텍스트-이미지와 이미지-이미지를 모두 지원하므로 사용자 지정 LoRA의 기반 모델로 적합합니다. diffusers은 두 작업 모두에 대한 DreamBooth LoRA 학습 스크립트를 제공합니다(Ostris’ AI Toolkit으로 학습할 수도 있습니다).

다음은 multimodalart/1920-raider-waite-tarot-public-domain 데이터셋에서 타로 카드 스타일을 학습하고 trtcrd로 활성화하는 텍스트-이미지 예제입니다:

accelerate launch train_dreambooth_lora_flux3_klein.py \
  --pretrained_model_name_or_path="black-forest-labs/flux-3-image-klein-base" \
  --dataset_name="multimodalart/1920-raider-waite-tarot-public-domain" \
  --caption_column="caption" \
  --instance_prompt="trtcrd" \
  --output_dir="trained-flux3-tarot-lora" \
  --mixed_precision="bf16" \
  --resolution=1024 \
  --use_aspect_ratio_buckets \
  --train_batch_size=1 \
  --rank=16 \
  --lora_alpha=16 \
  --learning_rate=1e-4 \
  --lr_scheduler="constant" \
  --max_train_steps=1500 \
  --validation_prompt="a trtcrd of a cat, tarot style" \
  --validation_epochs=25 \
  --seed=0 \
  --push_to_hub

[!NOTE] 메모리 사용량을 줄이려면 다음 최적화 플래그를 추가합니다:

  --gradient_checkpointing \
  --cache_latents \
  --use_8bit_adam

--gradient_checkpointing은 backward pass에서 activation을 다시 계산하고(더 낮은 VRAM, 약간 느린 속도), --cache_latents은 이미지를 미리 인코딩한 후 VAE를 해제하며, --use_8bit_adam는 optimizer state를 8-bit로 유지합니다.

몇 가지 설정은 직접 실험해 볼 가치가 있습니다. 아래 그리드는 서로 다른 LoRA rank와 optimizer를 사용해 동일한 타로 스타일을 학습한 결과이며, adapter는 Hub의 diffusers-modular/flux3-tarot-lora에 있습니다. 더 많은 학습 기능과 구성은 DreamBooth FLUX.3 README에 문서화되어 있습니다.

지시 기반 편집의 경우 이미지-이미지 스크립트(train_dreambooth_lora_flux3_klein_img2img.py)는 (참조 이미지, 대상 이미지, 지시) triplet으로 학습하며, 프롬프트에서는 참조 이미지를 <ref_image_0>로 지정합니다.

모든 옵션과 전체 이미지-이미지 예제는 DreamBooth FLUX.3 README을 참조하세요.

실행에 필요한 비용

이 섹션에서는 모델의 메모리 사용량과 생성 속도를 살펴봅니다.

메모리

이름 peak allocated (after load) GiBs peak allocated (after inference) GiBs
nvfp4 (RTX6000) 13.4 15.3
fp8r (H100) 14.35 16.27
bf16 (H100) 18.80 20.72

메모리가 더 적다면 다음을 수행할 수 있습니다:

  • quantized transformer을 로드합니다.
  • 텍스트 인코더를 별도로 실행한 뒤 해제합니다. 텍스트 인코더는 이미지당 한 번, denoising 전에만 실행됩니다(Encode once, generate many 참조).
  • 자동 CPU offloading을 활성화합니다. 각 구성 요소가 실행되는 동안에만 GPU로 이동합니다(이 방식은 벤치마크하지 않았습니다).
from diffusers import ComponentsManager, ModularPipeline

manager = ComponentsManager()
manager.enable_auto_cpu_offload(device="cuda")

pipe = ModularPipeline.from_pretrained("black-forest-labs/flux-3-image-klein", components_manager=manager)
pipe.load_components(dtype={"vae": torch.float32, "default": torch.bfloat16})
# no pipe.to("cuda"): the manager handles device placement

속도

증류 체크포인트(16 steps)의 end-to-end 측정 시간으로, warmup 후 3회 실행한 평균입니다:

워크플로 출력 크기 시간 최대 메모리
텍스트-이미지 1024 × 1024 1.93 s 23.8 GiB
이미지-이미지, 1024 × 1024 참조 이미지 1개 1024 × 1024 3.87 s 23.8 GiB
Layout editing(기사), 1360 × 768 참조 이미지 1개 1360 × 768 4.10 s 23.8 GiB

[!NOTE] 단일 NVIDIA H100 80GB, offloading 없음, 기본 attention backend.

참조 이미지가 있으면 시간이 대략 두 배로 늘어납니다. 참조 token은 텍스트 및 생성 중인 이미지와 동일한 sequence에 포함되므로, 1024 × 1024 참조 이미지는 각 transformer 호출에 4,096개의 token을 추가합니다.
transformer 호출당 token 수를 나타내는 누적 막대: 텍스트-이미지 4,256 token, 이미지-이미지 8,272, layout 텍스트-이미지 4,336, layout 이미지-이미지 8,800

아키텍처

모델을 한 부분씩 열어 살펴보겠습니다. 모델은 세 종류의 token을 입력으로 받습니다:

  1. 텍스트
  2. 생성 중인 노이즈 이미지
  3. 그리고 선택적인 참조 이미지

픽셀에서 token으로

FLUX.3은 이미지 생성을 위한 latent-space flow 모델입니다. 즉, denoiser는 latent를 입력으로 받아 latent를 출력합니다. VAE를 사용해 latent를 다시 픽셀로 디코딩합니다. FLUX.3은 Flux.2와 동일한 VAE 아키텍처를 사용합니다.

FLUX.2 VAE는 이미지를 각 방향으로 8× 압축해 32개 채널로 만들고, 그 latent의 2 × 2 patch마다 128개 채널을 가진 하나의 token으로 패킹합니다.

따라서 하나의 token은 16 × 16 픽셀 patch를 담당하며, 1024 × 1024 이미지는 4,096개의 token으로 구성된 64 × 64 grid가 됩니다. 노이즈 이미지는 정확히 이 형태의 무작위 noise로 시작합니다. 참조 이미지는 동일한 VAE 인코더와 패킹 과정을 거치며, 자체 크기를 유지합니다.

프롬프트에서 token으로

텍스트 인코더는 vision-language 모델인 Qwen3-VL입니다. FLUX.3은 마지막 layer만 사용하지 않습니다. 36개 layer 중 8개(layers 4, 8, …, 32)의 hidden state를 읽고 쌓아 각 텍스트 token을 8 × 2560 = 20,480차원 벡터로 만든 다음, linear layer를 통해 transformer의 너비인 3072로 투영합니다.

이를 통해 transformer는 언어 모델의 최종 layer뿐 아니라 여러 깊이의 feature를 사용합니다. 프롬프트는 80 token의 배수로 padding되며, transformer는 padding에도 attention을 수행합니다. 이것이 pipeline이 호출당 하나의 프롬프트만 받는 이유입니다.

두 단계

transformer는 token을 두 단계로 처리합니다:

  1. 1단계: 모드별 블록. 각 stream은 자체 가중치를 사용하는 5개 블록을 통과합니다. 텍스트에는 자체 블록이 있고, 노이즈 이미지에도 자체 블록이 있으며, 참조 이미지에도 자체 블록이 있습니다.
  2. 2단계: joint 블록. stream을 하나의 sequence로 연결한 [text | image | reference]이(가) 하나의 가중치 세트를 공유하는 28개 블록을 통과합니다.

두 단계는 누가 누구에게 attention할 수 있는지가 다릅니다.

1단계에서는 각 stream이 자기 자신에게만 attention하므로 각 종류의 token이 먼저 자체 특성에 맞게 정제됩니다. 2단계에서는 모든 요소가 서로에게 attention하며, 이미지가 텍스트와 참조 이미지에서 학습합니다. 비교하면 FLUX.2의 double-stream 블록도 텍스트와 이미지에 서로 다른 가중치를 사용하지만, 처음부터 서로에게 attention할 수 있게 합니다. FLUX.3은 먼저 stream을 완전히 분리한 다음 병합합니다.

마지막에는 텍스트와 참조 token을 단순히 제거합니다. 이미지 token만 output layer를 통과하며, output layer는 이미지를 한 단계 더 깨끗한 이미지에 가깝게 이동하는 방법을 예측합니다.

하나의 블록 내부

두 단계 중 어느 단계에 있든 모든 블록은 동일한 형태를 가집니다. Attention과 MLP는 동일하게 정규화된 입력에 대해 병렬로 실행되며, 두 결과의 합이 residual stream에 다시 더해집니다.

각 블록은 자체적으로 학습된 scale이나 shift가 없는 LayerNorm으로 시작합니다. 대신 scale, shift, gate는 timestep embedding에서 가져옵니다(이를 modulation이라고 합니다). Attention 내부에서 query와 key는 RMS-normalize되고 rotary position embedding(RoPE)을 적용받습니다. 이에 대해서는 아래에서 살펴봅니다.

Joint 블록에서는 모든 token이 동일한 가중치를 공유하지만, 텍스트, 이미지, 참조 token에는 각각 고유한 scale, shift, gate가 적용됩니다.

def block(x, shift, scale, gate):      # shift, scale, gate come from the token's timestep embedding
    h = layer_norm(x)                  # no learned scale or shift
    h = (1 + scale) * h + shift
    q, k, v = to_q(h), to_k(h), to_v(h)
    q, k = rope(rms_norm(q)), rope(rms_norm(k))
    out = attention(q, k, v) + mlp(h)  # parallel, MLP is SwiGLU
    return x + gate * out

모든 token에 고유한 timestep이 적용됩니다

FLUX.1과 FLUX.2에서는 하나의 timestep embedding이 모든 token을 modulation합니다. FLUX.3에서는 token의 종류에 따라 modulation이 달라집니다.

노이즈 이미지 token은 현재 timestep t에 의해 modulation됩니다. 텍스트와 참조 token은 항상 timestep 0으로 modulation되며, 이는 “깨끗하므로 여기서는 denoise할 것이 없음”을 의미합니다. 따라서 출력과 거의 동일해 보이는 참조 이미지도 생성할 대상이 아니라 주어진 context로 표시됩니다.

증류 체크포인트는 flow map입니다. 또한 각 단계가 어디까지 이동하는지 나타내는 timestep도 전달받습니다. 이 두 번째 timestep은 자체 embedding을 가지며 모든 token의 modulation에 더해집니다. 따라서 16개 step 각각에서 더 큰 폭으로 이동할 수 있습니다.

4차원 위치

Attention만으로는 token의 위치를 알 수 없습니다(이 현상을 permutation equivariance라고 합니다). RoPE는 token의 위치에 따라 달라지는 양만큼 각 query와 key를 회전시켜 이 문제를 해결합니다. FLUX.3은 네 가지 위치 축인 (t, h, w, l)(timestep, height, width, sequence length)을 사용하며, 각 축에 128차원 attention head의 4분의 1(32차원)을 할당합니다:

Token t: timestep h: height w: width l: sequence length
텍스트 token i 0 0 0 i
(row, col)의 이미지 token 0 row / 2 col / 2 0
(row, col)의 참조 k 0 row / 2 col / 2 −(k + 1)

텍스트 token은 문장의 단어처럼 l을 따라 나란히 배치됩니다. 이미지와 참조 이미지는 (h, w)의 2D grid이며, 서로 l을 따라 분리됩니다. 참조 이미지는 출력과 동일한 (h, w) 좌표를 사용하므로 “참조 이미지의 동일한 위치”가 모델에 정확한 의미를 갖습니다. 이것이 src_bbox / tgt_bbox 편집의 기반입니다.

Denoising loop

FLUX.3은 flow-matching 모델입니다. 생성은 순수한 noise에서 시작하며, 50개 step 각각에서 transformer가 velocity를 예측합니다. 이는 noise에서 깨끗한 이미지로 향하는 방향입니다. scheduler는 그 방향을 따라 한 step 이동합니다.

각 step에서 모델이 최종 이미지로 현재 추정하는 결과도 확인할 수 있습니다. 몇 개의 step에서 이 추정 결과를 디코딩하면 이미지가 어떻게 형성되는지 볼 수 있습니다:
Step 1 Step 5 Step 10 Step 15 Step 25 Step 50

여우와 자세, 조명은 이미 step 10에서 자리 잡지만 noise level은 여전히 0.97입니다. 눈이 쌓인 나뭇가지와 털의 질감은 마지막 몇 step에서야 나타납니다. FLUX.3의 scheduler는 큰 time shift(6.93)를 사용하므로 실행 대부분에서 noise level을 높게 유지합니다. 50개 step 중 44개가 σ = 0.5보다 높은 상태에서 수행됩니다. 이 그림은 pipeline에 작은 블록 하나를 추가해 만들었으며, 이제 Modular Diffusers로 이어집니다.

[!NOTE] flow matching이 처음이라면 작동 방식을 이해할 수 있도록 초보자용 friendly tutorial과 video을 제공합니다.

Modular Diffusers

FLUX.3은 Modular Diffusers pipeline으로 제공됩니다.

워크플로 확인하기

가중치를 로드하지 않고도 워크플로를 나열하고 각 워크플로의 정확한 블록을 출력할 수 있습니다.

from diffusers import Flux3AutoBlocks

blocks = Flux3AutoBlocks()
print(blocks.available_workflows)
# ['text2image', 'image_conditioned']

print(list(blocks.get_workflow("text2image").sub_blocks))
# ['text_encoder', 'denoise.input', 'denoise.prepare_latents', 'denoise.set_timesteps',
#  'denoise.prepare_rope_inputs', 'denoise.denoise', 'denoise.after_denoise', 'decode']

get_workflow()은 auto branch를 해석해 실제로 실행될 단계의 일반 sequence를 제공합니다. print(blocks.get_workflow("image_conditioned").doc)은 해당 워크플로의 구성 요소, 입력, 기본값, 출력을 출력합니다.

한 번 인코딩하고 여러 번 생성하기

텍스트 인코더를 분리하고 프롬프트를 한 번 인코딩한 뒤, 이를 해제하고 캐시된 embedding으로 생성합니다.

import torch
from diffusers import ModularPipeline

model_id = "black-forest-labs/flux-3-image-klein-base"

blocks = ModularPipeline.from_pretrained(model_id).blocks
text_blocks = blocks.sub_blocks.pop("text_encoder")  # `blocks` now starts at the VAE encoder

text_pipe = text_blocks.init_pipeline(model_id)
text_pipe.load_components(dtype=torch.bfloat16)
text_pipe.to("cuda")

state = text_pipe(prompt=prompt, negative_prompt="")  # no guider here, so ask for the negative embeddings

prompt_embeds = state.get("prompt_embeds")
negative_prompt_embeds = state.get("negative_prompt_embeds")

del text_pipe
torch.cuda.empty_cache()

image_pipe = blocks.init_pipeline(model_id)  # no text encoder to load
image_pipe.load_components(dtype={"vae": torch.float32, "default": torch.bfloat16})
image_pipe.to("cuda")

for seed in range(3):
    image = image_pipe(
        prompt_embeds=prompt_embeds,
        negative_prompt_embeds=negative_prompt_embeds,
        generator=torch.Generator().manual_seed(seed),
        output="images",
    )[0]
    image.save(f"{seed}.png")

Loop 내부에 step 추가하기

위의 denoising 그림은 각 step에서 모델의 깨끗한 이미지 추정 결과를 기록하는 추가 블록 하나에서 생성되었습니다:

from diffusers.modular_pipelines import Flux3AutoBlocks, InputParam, ModularPipelineBlocks, OutputParam


class Flux3PreviewStep(ModularPipelineBlocks):
    model_name = "flux3"

    @property
    def inputs(self):
        return [InputParam("latents"), InputParam("noise_pred")]

    @property
    def intermediate_outputs(self):
        return [OutputParam("x0_previews", type_hint=list)]

    @torch.no_grad()
    def __call__(self, components, block_state, i, t):
        if i == 0:
            block_state.x0_previews = []
        sigma = t / 1000  # timesteps are sigmas scaled to [0, 1000]
        block_state.x0_previews.append(block_state.latents - sigma * block_state.noise_pred)  # x0 = x_t - sigma * v
        return components, block_state


blocks = Flux3AutoBlocks()
denoise_loop = blocks.sub_blocks["denoise"].sub_blocks["text2image"].sub_blocks["denoise"]
denoise_loop.sub_blocks.insert("preview", Flux3PreviewStep(), 1)  # between "denoiser" and "after_denoiser"

pipe = blocks.init_pipeline(model_id)
pipe.load_components(dtype={"vae": torch.float32, "default": torch.bfloat16})
pipe.to("cuda")

out = pipe(prompt=prompt, generator=torch.Generator().manual_seed(0), output=["x0_previews", "images"])
