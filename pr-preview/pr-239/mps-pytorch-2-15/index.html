이 글은 Hugging Face 블로그의 MPS in PyTorch 2.15를 한국어로 번역한 글입니다.

PyTorch 2.15의 MPS

Mac에서 모델을 실행하거나 컴퓨팅을 위한 주요 가속 도구로 MPS를 사용한다면, PyTorch 2.15에서 기대할 만한 소식이 많습니다! MPS에 FP8이 도입되고, 선형 레이어와 softmax를 통한 언어 모델 디코딩 경로가 빨라졌으며, 새로운 Metal 커널이 오디오, 비디오 및 학습 워크로드에서 예상보다 많은 비용이 드는 일부 작업을 처리합니다.

먼저 저희가 누구인지 간단히 말씀드리겠습니다. 저희는 Hugging Face의 PyTorch 팀입니다. PyTorch 전반에 기여하고 있으며, 주요 관심 분야 중 하나가 MPS 백엔드입니다. 목표는 Mac을 PyTorch 모델을 실행하고 학습하기에 가장 우선적으로 고려할 수 있는 환경으로 만드는 것입니다. 2026년 초에는 MPS에서 작은 모델 하나를 실행하는 것조차 지원되지 않는 연산, 급격한 성능 저하, 예상치 못한 메모리 증가를 우회해야 하는 경우가 많았습니다. 그래서 Hugging Face Hub의 실제 언어, 이미지, 비디오 모델을 실행하면서 MPS가 부족한 지점을 찾고, PyTorch에서 업스트림으로 이를 수정하고 있습니다. 최근에는 MPSGraph를 전용 Metal 커널로 대체하는 방식이 점점 더 많아지고 있습니다. 이 글의 상당 부분은 PyTorch 유지 관리자 및 커뮤니티 기여자들과 함께 수행한 이 작업의 결과입니다.

TL;DR

  • FP8이 Mac에 도입됩니다: float8_e4m3fn 값을 BF16의 절반 공간에 저장하고, CUDA/CPU에서 지원되는 모든 연산과 scaled matrix multiplication을 사용할 수 있습니다!
  • MoE 모델 디코딩이 2.14보다 5~6.5배 빨라집니다: 전용 디코딩 경로를 갖춘 네이티브 grouped matmul, GPU-CPU 동기화 감소, 더 빠른 top-k 라우팅 덕분에 M3 Ultra에서 Qwen3.6-35B-A3B가 9.4 tokens/s에서 61.3 tokens/s로 빨라집니다.
  • 모든 LLM에서 토큰당 시간이 단축됩니다: 단일 행 선형 레이어가 특수 행렬-벡터 커널을 사용하고, vocabulary에 대한 softmax가 약 8배 빨라집니다.
  • GPU에서 더 많은 선형 대수 연산을 처리합니다: 복소수 LU 및 삼각 시스템 풀이, 더 빠른 소행렬 역행렬 계산, 더 빠른 QR 분해를 지원합니다.
  • 오디오, 비디오, 학습도 개선됩니다: convolution, padding, dropout, interpolation backward 및 reduction을 위한 더 빠른 경로가 추가됩니다. Wan2.2의 비디오 VAE 디코딩은 이제 메모리 사용량이 최대 270 GiB가 아닌 8 GiB에 이릅니다.
  • Python에서 더 많은 제어가 가능합니다: public MPS streams와 더 안정적인 event timing을 제공합니다.
  • 요구 사항이 변경되었습니다: 이제 MPS에는 macOS 15 이상이 필요하며, PyTorch 2.15에는 Python 3.11 이상이 필요합니다.
  • 2.16 미리 보기: attention을 전부 Metal에서 실행하고, MPSGraph-to-Metal 마이그레이션을 확대하며, LLM 디코딩을 더 빠르게 만듭니다.

이것이 사용자에게 의미하는 것

Mac에서 transformers, diffusers 또는 ComfyUI와 같은 도구로 모델을 실행한다면, 2.15에서 실제로 달라지는 점은 다음과 같습니다.

  • 로컬 LLM이 훨씬 빨라집니다. Mixture-of-experts 모델의 디코딩이 2.14보다 5~6.5배 빨라집니다. torch.compile을 사용하는 M3 Ultra에서 Qwen3.6-35B-A3B는 9.4 tokens/s에서 61.3 tokens/s로, LFM2.5-8B-A1B는 23.6 tokens/s에서 123.6 tokens/s로 향상됩니다. Dense 모델도 더 빠른 선형 레이어와 샘플링 시 8배 빨라진 softmax의 이점을 얻습니다. (More)
  • 메모리에 들어가는 비디오 생성이 가능합니다. Wan2.2의 tiled VAE로 비디오를 디코딩하면 이전에는 드라이버 메모리가 270 GiB까지 증가했지만, 이제는 약 8 GiB에서 정점을 이룹니다. (More)
  • Qwen-Image-2.1을 사용한 올바른 이미지 편집이 가능합니다. 2.14에서는 Qwen-Image-2.1 VAE encoder가 MPS에서 이미지를 조용히 손상시켜 이미지 편집 워크플로를 망가뜨렸습니다(reported in ComfyUI). same padding change에서 이 문제가 수정되었습니다. 이제 encode-decode 왕복 결과가 CPU와 일치하며 PSNR이 10.06 dB에서 29.95 dB로 향상됩니다.
  • Mac에서 FP8 가중치를 사용할 수 있습니다. FP8 tensor는 BF16의 절반 메모리만 사용하며, F.scaled_mm가 이를 GPU에서 직접 곱합니다. (More)

시작하기

macOS 15 이상 및 Python 3.11 이상을 사용하는 Apple silicon Mac이 필요합니다(2.15 compatibility matrix 참조). OS가 너무 오래되었거나 Metal GPU를 사용할 수 없는 경우, 이제 MPS availability check가 그 이유를 알려줍니다.

별도 환경에서 release candidate를 사용해 보려면 다음을 실행하세요.

uv pip install torch==2.15.0 --index-url https://download.pytorch.org/whl/test/cpu

MPS에 FP8 도입

FP8은 Mac에서 메모리를 절약할 수 있는 또 하나의 방법입니다. PyTorch 2.15는 MPS에서 torch.float8_e4m3fn tensor를 추가합니다. 값당 1바이트로, FP16 또는 BF16의 절반에 해당하는 저장 공간만 사용합니다.

F.scaled_mm을 사용해 이러한 tensor를 곱할 수 있으며, tensorwise scaling과 rowwise scaling을 모두 지원합니다. 다음은 tensor당 하나의 scale을 사용하는 간단한 예입니다.

import torch
import torch.nn.functional as F

def quantize_fp8(x):
    limit = torch.finfo(torch.float8_e4m3fn).max
    scale = x.abs().amax().clamp_min(1e-12) / limit
    return (x / scale).to(torch.float8_e4m3fn), scale

x = torch.randn(1, 1024, device="mps", dtype=torch.float32)
weight = torch.randn(1024, 1024, device="mps", dtype=torch.float32)
x_fp8, x_scale = quantize_fp8(x)
w_fp8, w_scale = quantize_fp8(weight)

y = F.scaled_mm(
    x_fp8,
    w_fp8.t(),
    scale_a=x_scale,
    scale_recipe_a=F.ScalingType.TensorWise,
    scale_b=w_scale,
    scale_recipe_b=F.ScalingType.TensorWise,
    output_dtype=torch.bfloat16,
)
print(y.shape, y.dtype)

더 빨라진 언어 모델 디코딩

모든 LLM에는 prefill 단계와 decode 단계가 있습니다. decode 중에는 새 토큰 하나가 단일 행으로 모델을 통과하므로, 큰 행렬 곱셈이 행렬-벡터 곱으로 바뀝니다. PyTorch 2.15는 이 단계의 대부분을 차지하는 두 종류의 레이어, 즉 dense 선형 레이어와 mixture-of-experts 레이어를 모두 가속합니다.

선형 레이어

MPS에는 2.14부터 torch.mm용 GEMV 커널이 있었지만, F.linear은 여전히 MPSGraph를 거쳤습니다. PyTorch 2.15는 connects them to F.linear하므로, 일반적인 [1, 1, hidden_size] 디코딩 입력이 이를 직접 사용하며, 조건에 맞는 bias addition도 함께 fuse됩니다. 실제 모델에서 가져온 96개의 BF16 레이어 shape 전체에서 기하 평균 1.23배의 속도 향상을 보입니다. 가장 큰 개선은 작은 projection에서 나타납니다. 예를 들어 MoE 모델의 gate에서는 기존 경로가 메모리 대역폭 대부분을 사용하지 못했습니다. 대형 레이어와 LM head는 이미 대역폭 제한에 가까웠으므로 약 1배 수준을 유지합니다.

Mixture-of-experts 레이어

Mixture-of-experts 레이어는 서로 다른 수의 토큰을 각 expert로 보냅니다. Grouped matmul은 이러한 불균일한 그룹을 하나의 연산으로 처리하며, 2.15에서는 MPS에 native implementation을 제공합니다.

2.14에서 grouped matmul은 그룹 offset을 CPU로 복사한 다음 그룹을 반복 처리했습니다. 새로운 Metal 커널은 GPU에서 offset을 직접 읽으며, 가능한 경우 Metal Performance Primitives를 사용하고 그 외에는 별도의 Metal 경로를 사용합니다. 디코딩 중 일반적으로 발생하는 작은 그룹도 their own kernel을 얻습니다.

예를 들어 64개의 토큰을 16개, 32개, 16개의 그룹으로 나눌 수 있습니다.

import torch
import torch.nn.functional as F

tokens = torch.randn(64, 64, device="mps", dtype=torch.bfloat16)
weights = torch.randn(3, 128, 64, device="mps", dtype=torch.bfloat16)
ends = torch.tensor([16, 48, 64], device="mps", dtype=torch.int32)

out = F.grouped_mm(tokens, weights.transpose(-2, -1), offs=ends)
print(out.shape)  # torch.Size([64, 128])

디코딩 커널은 토큰 처리량에 직접적인 영향을 줍니다. torch.compile을 사용하는 M3 Ultra에서 MoE 모델은 초당 약 1.3배 더 많은 토큰을 생성합니다.

선형 대수 성능 향상

복소수 값 계산

복소수 tensor를 더 쉽게 다룰 수 있습니다. complex64 LU factorization, LU solve 및 triangular solve이 이제 MPS에서 실행되며, 이에 기반한 연산과 gradient도 사용할 수 있게 됩니다. 예를 들어 복소수 determinant가 있습니다. 다음은 GPU에서 직접 푼 간단한 시스템입니다.

import torch

a = torch.randn(8, 8, device="mps", dtype=torch.complex64)
a = a + 8 * torch.eye(8, device="mps", dtype=torch.complex64)
b = torch.randn(8, 2, device="mps", dtype=torch.complex64)

lu, pivots = torch.linalg.lu_factor(a)
x = torch.linalg.lu_solve(lu, pivots, b)
print((a @ x - b).abs().max().item())

소행렬과 대규모 시스템 풀이

소행렬에도 빠른 커널이 추가됩니다. 카메라 geometry와 이미지 변환을 위해 최대 4 × 4 크기의 FP32 행렬 batch가 이제 factorization과 solving을 결합한 inverted in a single Metal kernel입니다. 더 큰 문제도 개선됩니다. QR uses blocked updates 및 triangular solves는 작업의 상당 부분을 효율적인 행렬 곱셈으로 변환합니다.

Gated DeltaNet 워크로드는 16 × 16, 32 × 32 및 64 × 64 FP32 삼각 시스템 batch에서, right-hand side가 8개 이상일 때 dedicated fast path을 얻습니다.

SVD도 수치적 극단값에서 더욱 안정적으로 동작합니다. 이제 very small singular values, very large or very small input magnitudes 및 basis completion with full_matrices=True을 올바르게 처리하므로 pseudoinverse와 least-squares 결과도 더 신뢰할 수 있습니다.

Convolution, padding 및 학습

오디오 모델, 비디오 디코더 및 학습 loop에는 각각 비용이 큰 연산이 있습니다. 이번 릴리스에서는 이러한 연산 중 여러 가지에 새로운 Metal 경로를 제공합니다.

연산 2.15에서 변경되는 사항
conv1d forward 특수 커널이 MPSGraph를 대체하며, 짧은 출력용 im2col-plus-matmul 경로도 추가됩니다. 오디오 및 streaming-model shape에 유용합니다.
Constant padding Metal 커널로 전환되어 tiled video VAE 디코딩에서 드라이버 메모리가 폭발적으로 증가하던 문제가 수정됩니다(자세한 내용은 아래 참조).
Reflection and replication padding 더 빠르고 backward 정확성 문제를 수정한 새로운 Metal 구현이 추가됩니다.
Out-of-place dropout nn.Dropout 및 F.dropout가 이제 기존 fused kernel을 사용합니다.
Upsampling backward Metal gather 커널이 MPSGraph resize-gradient 경로를 대체합니다.
Channels-last conv2d backward 비용이 큰 strided access를 사용하는 NCHW graph 대신 효율적인 channels-last 경로를 유지합니다.

Softmax 및 reduction

토큰 샘플링도 2.15에서 빨라집니다. softmax 및 log_softmax이 이제 전용 Metal 커널에서 실행되며, 큰 vocabulary에서 가장 큰 이점을 얻습니다. [1, 128256] logits 행에 대한 FP32 softmax가 57 µs에서 7 µs로 줄어들어 MPSGraph 버전보다 약 8배 빨라집니다. 다른 일반적인 vocabulary 크기에서도 이러한 속도 향상이 유지됩니다.

비디오 디코딩에서 훨씬 작아진 메모리 사용량

이번 릴리스에서 가장 눈에 띄는 결과 중 하나는 constant-padding 변경에서 나옵니다. Wan-AI/Wan2.2-TI2V-5B-Diffusers의 VAE decode는 28개 타일 전체를 디코딩하는 동안 8,764회의 padding 호출을 수행합니다. Metal에서 padding을 처리하면 드라이버 메모리 정점이 약 270 GiB에서 8 GiB로 감소합니다.

메모리 지표 MPSGraph padding Metal padding
현재 tensor-allocation 정점 4.422 GiB 4.095 GiB
Allocator-reserved 정점 8.070 GiB 8.070 GiB
전체 driver-memory 정점 270.135 GiB 8.108 GiB

MPS streams로 더 많은 제어

이제 Python에서 직접 어떤 MPS stream이 작업을 실행할지 선택할 수 있습니다. torch.mps.Stream and the torch.mps.stream context manager이 인터페이스를 제공하며, Tensor.record_stream을 사용하면 allocator가 다른 stream에서 tensor가 사용되는 상황을 추적할 수 있습니다.

다음은 별도의 stream으로 작업을 보내고 결과를 읽기 전에 동기화하는 간단한 예입니다.

import torch

x = torch.randn(1024, device="mps")
torch.mps.synchronize()
worker = torch.mps.Stream()

with torch.mps.stream(worker):
    y = x.square()
    x.record_stream(worker)

del x
worker.synchronize()
print(y.cpu().shape)

더 많은 연산이 MPS에서 실행됩니다

이제 몇 가지 연산이 추가로 MPS에서 실행됩니다. torch.frexp, torch.logspace, torch.take and Tensor.put_, torch.heaviside, torch.special.laguerre_polynomial_l 및 unsigned-integer comparisons입니다. logspace은 아직 원소가 두 개보다 많은 integer 또는 boolean 출력을 지원하지 않습니다.

Attention에도 정확성 수정이 적용됩니다. scaled dot-product attention의 MPS math 구현이 이제 handles batch and head broadcasting correctly합니다.

PyTorch 2.16 미리 보기

2.16 작업은 이미 순조롭게 진행되고 있습니다. 아래 변경 사항 중 일부는 main에 반영되어 nightlies에서 사용할 수 있으며, 다른 변경 사항은 아직 검토 중이므로 릴리스 전 세부 사항이 달라질 수 있습니다.

더 빨라진 LLM 디코딩

모델의 decode 경로에 MPSGraph 연산이 더 이상 포함되지 않으면, CPU가 모든 커널 인코딩을 완료한 뒤에야 GPU가 토큰 처리를 시작합니다. PyTorch 2.16은 commits the command buffer every 16 kernels하므로 CPU가 나머지를 계속 인코딩하는 동안 GPU가 작업을 시작할 수 있습니다. 2048토큰 context에서 compiled BF16 디코딩을 수행한 결과는 다음과 같습니다.

모델 이전 이후 변경
LFM2.5-8B-A1B 108.8 tokens/s 126.0 tokens/s +16%
Qwen3.6-35B-A3B 52.9 tokens/s 62.8 tokens/s +19%
Qwen3.8-27B 12.1 tokens/s 12.6 tokens/s +4%

Attention을 전부 Metal에서 실행

Scaled dot-product attention이 dropping MPSGraph completely됩니다. 모든 shape이 Metal 커널에서 실행되며, 디코딩에는 전용 vector 커널을 사용하고 최신 macOS 버전의 half-precision prefill에는 Metal Performance Primitives를 사용합니다. 이전에 MPSGraph로 fallback하던 shape에서 가장 큰 이점을 얻습니다. M5 Pro에서 grouped-query attention(32 query heads, 8 KV heads, head dim 80, 4K context)을 사용한 디코딩은 465 µs에서 65 µs로, head dim 40의 4K × 4K prefill은 42 ms에서 6 ms로 감소합니다.

MPSGraph에서 Metal로의 추가 마이그레이션

MPSGraph에서 벗어나는 작업이 계속되고 있습니다. Batch norm forward 및 backward이 진행 중이며, MSE loss(작은 입력에서 최대 12배 빠름), std_mean and var_mean(최대 4배 빠름) 및 bincount는 이미 반영되었습니다. bincount의 변화가 가장 극적입니다. 대부분의 값이 단일 bin에 속하는 경우, 400만 개의 정수를 세는 데 걸리던 시간이 6.8초에서 이제 0.5밀리초로 줄어듭니다.

더 작아진 설치 용량

번들로 제공되는 shader가 build for Metal 3.1 by default되며, Metal 4 버전은 필요한 커널에 대해서만 컴파일됩니다. 그 결과 libtorch_cpu.dylib가 약 25% 줄어들어 384 MiB에서 287 MiB가 되며, 더 빠른 matmul과 native FP8 matrix multiplication을 지원하는 Metal 4.1 shader를 위한 기반도 마련됩니다.

마무리

PyTorch 2.15는 Mac에 FP8을 도입하고, dense 및 MoE 모델의 LLM 디코딩을 가속하며, GPU에서 더 많은 선형 대수 연산을 처리하고, MPSGraph에서 전용 Metal 커널로 전환된 다양한 연산을 제공합니다. release candidate를 사용해 보세요!

앞으로의 계획

  • 더 많은 MPS 개선: 2.16에서는 attention을 전부 Metal에서 실행하며, 계속해서 연산을 MPSGraph에서 이전할 예정입니다.
  • torch.compile: 더 많은 모델이 end to end로 컴파일되도록 graph break를 제거하는 작업을 진행하고 있습니다.
  • 여러분의 아이디어: PyTorch에서 다음으로 어떤 작업을 진행하면 좋을까요? MPS든 다른 곳이든 느리거나, 누락되었거나, 제대로 동작하지 않는 부분이 있다면 open an issue on GitHub 알려 주세요.

이번 작업의 상당 부분을 검토해 주신 Nikita Shulga, Kurt Mohler 및 Aaron Gokaslan께 감사드리며, 이번 릴리스에서 MPS에 기여해 주신 모든 분께도 감사드립니다.
